# 11節の構成テンプレートと各節の書き方

> 節番号は HTML では `01 / MAP` 形式の `sec-label` に対応させる。
> 対象によって不要な節は落としてよいが、**§01（層の地図）・§04（障害）・§10（言えること／言えないこと）・
> §11（参照マップ）の4つは落とさない**。この4つがこの型の骨格。

---

## §00 位置づけ（冒頭の引用ブロック）

md では `>` 引用ブロック、HTML では `.lede` に置く。次の3点を書く。

1. **何をした文書か**: 「散在している数式を一本の筋で追えるようにした学習用ノート」
2. **新規性の否認**: 「新規の主張・新規の実測値はない（既報値の再掲のみ）」
   — これを書かないと、まとめ文書が新結果と誤読される
3. **既存文書に無かった点の予告**: Phase 0 で確定した欠落を列挙（§11 で再掲）

```markdown
> 位置づけ: 既存ノートに散在している数式を、**「何を測りたいか → なぜ素朴には測れないか →
> だからこの測り方になる」** という一本の筋で追えるようにした学習用ノート。新規の主張・
> 新規の実測値はない。既存ノートに書かれていなかった3点を明示的に埋めている: (a) …
```

## §01 MAP — 層の地図

**本文より前に置く。** 混乱の主因は記号の共有なので、最初に対象を分離する。

- 表で `層 / 変数 / 条件付け / そこで言える式 / 使う場面` を並べる
- 既存文書がどの層を扱っているかを明記（「基礎語彙ノートは層1だけ」）
- 層の間の矢印に**何をして降りたか**を書く（chain rule / 粗視化 / 周辺化）
- 特に混同しやすい記号のペアは `.note.warn` で警告する
  （例: $H(X\mid S)$ と $H(p_i \mid h_i)$ は条件付けの対象が別）

HTML では `.layer-map` を使う。層の色は indigo → teal → amber の順（主系統 → 厳密 → 一般化）。

## §02 出発点 — 測定量の定義

「何を測っているのか」の最小の定義。ここで**単位を確定**させる。

- 測定量が達成可能であることの根拠（符号長なら Kraft + 算術符号、実装なら該当コード）
- 正規化の定義（per-byte / per-token / per-record）を式で書く
- 「以降に出る数値はすべてこの正規化がかかっている」と明記

## §03 恒等変形 — 分解の導出

**結果だけ書かない。** 1行の変形でも導出を書き、各行に注記を添える。

- `aligned` 環境で `=` を縦に揃える
- `.derive` の箇条書きで「2行目: ◯◯を掛けて割っただけ」と各行を説明
- 分解の各項を表にして `項 / 意味 / 性質（測れる・下回れない・非負）` を並べる
- 記号が複数箇所に登場する場合、**登場箇所を明示した式**を別に書く
  （例: $p$ は期待値の添字に1回、右辺に2回）
- `.note.strict`（teal）で「これは近似ではなく恒等式。仮定は◯◯だけ」と締める

## §04 THE OBSTACLE — なぜ素朴には測れないか

**この節が手法の存在理由。** 省くと「なぜそんな面倒なことをするのか」が伝わらない。

- 等式は成立するのに**個別の項が計算できない**理由を書く（真の分布が観測不能、など）
- 具体的な実測値を入れて「この数字の内訳が決まらない」と示す
- 図（`.barfig`）で「測れる量」と「割れない内訳」を対比する
- 回避策の部分解（差分をとる等）があれば触れ、それでも残る限界を明記
- `.answer`（teal 枠）で「だからこの手法が存在する」と結論を置く

## §05 橋 — 層を降りる

§01 の矢印を式で実行する。**2種類を区別するのが要点**（混同されやすい）。

- 実現値レベルで成立する分解（期待値不要）と、期待値レベルでのみ成立する分解を分ける
- 降りた先の式を `.card` で強調し、「**この式が既存ノートのどこにも無かった層**」と明記

## §06 定理 — 仮定を明示して等号を出す

- **唯一の仮定**を `.note` で先に置く（「以降の等号はすべてこの仮定の上に載る」）
- 仮定から特殊な構造（点質量など）が出ることを式で示す
- そこから等号を**直接計算**して見せる（定義に代入するだけの計算でも省かない）
- `.note.strict` で「厳密性の要点」を箇条書き（例: 期待値を取る必要がない理由）
- 対比する側（一般の位置）で何が起きるかを図（`.dist`）で並置する

## §07 実装とその破れ

- `.compare` で2つの実装を対比（近似版 = plum、厳密版 = teal）
- 各版の**破れを数える**（会計の失敗 / 交絡 / 未証明ギャップ）
- 破れの共通の根本原因を1文で書く（「測定単位に実装物を使った」など）
- 既存の図が誤読を誘発している場合、**その図の読み方を確定させる小節**を置く
  （`.answer` で「会計の図としてはこれが正しい。壊れていたのは問いと集計の不一致」）

## §08 一般化 — 要求を弱める

- 新しい定義を箇条書きで（記号の意味を1行ずつ）
- 恒等式を示し、「なぜ厳密か」を別小節で証明（粗視化・データ処理不等式など）
- **効いている点を番号付きで列挙**（何が不要になったか、何が消えたか、何の特殊例か）
- 「厳密に扱うべき残りの注意点」を表で（誇張の防止）。未実施項目に `.pill.todo`
- 既存の実験系との接続を書く（この手法で測ると何が見えるか）

## §09 対応表 — 問い × 層 × 集計 × 図 × 状態

**1枚の表で全体の現在地を示す。** 読者が「今どこまで出来ているか」を掴む節。

| 問い | 層 | 集計 | 図 | 状態 |
|---|---|---|---|---|

- 状態列には `実測済` / `未実施` の pill を入れる
- 集計方法の注意（層別が必要な変数など）を表の後に補足

## §10 SCOPE — 言えること・言えないこと

- `.note.strict`（teal）に「言える」、`.note.warn`（shu）に「言えない」
- 「言える」には仮定の個数を再掲する
- 「言えない」には未実測・未検証・原理的限界を分けて書く
- 最後に**誇張しない言い方**を1文で示す（「完全に分離」ではなく「◯◯成分を下から押さえる」）

## §11 参照マップ

- 表で `内容 / 所在（ファイル + 行番号）`。既存文書のどこに何があるかを一覧化
- **「本ノートで新しく明文化したもの」を別ブロックで列挙**（Phase 0 の結論）
- 主要文献を箇条書き（何をした論文で、この研究のどこに効くか）
